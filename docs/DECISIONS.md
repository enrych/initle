# Decision log

Every architectural choice, tradeoff and shortcut taken while building Initle v2, for review.
Format: **decision**, why, and what it costs us. Newest at the bottom.

| # | Area | Decision | Why | Cost / revisit when |
|---|---|---|---|---|
| 1 | Platform | Cloudflare Workers + one Durable Object per room (via `partyserver`) | One authoritative, stateful instance per room, built-in WebSockets, hibernation, scales per-room with no servers to run | Vendor lock-in. Game logic is a pure reducer in `packages/core` with no Cloudflare imports, so only the thin transport moves |
| 2 | Repo | Rewrite from scratch on branch `v2-m1`; v1 code deleted (still in git history). v1 board and origin screenshot moved to `docs/` | v1 shapes (Express in-memory maps, REST join) don't fit the new design | None; history is preserved |
| 3 | Monorepo | pnpm workspaces: `packages/core`, `apps/server`, `apps/web`; core consumed as TS source (no build step) | Simplest setup; Vite and Wrangler (esbuild) both compile TS directly | Core can't be published as-is; fine for an app |
| 4 | Game logic | Pure `reduce(state, action, now)` with time passed in, randomness passed in (`seed`, `items`) | Deterministic, unit-testable without network or clocks; same code can run anywhere | Server must pick items/seed before dispatching |
| 5 | Sync model | Server sends the full per-player `view` after every change (no diffs) | Reconnect is trivial, no drift bugs; views are 2–5 KB at 10 players | More bytes than diffs; irrelevant at party scale |
| 6 | Timers | Phase deadlines stored in state; DO alarm fires `tick`; reducer catches up over missed deadlines | Survives DO hibernation/eviction; clients render countdown from `deadline` + clock offset | Alarm granularity (~ms–100ms) is fine for 8s stages |
| 7 | Matching | Word-by-word lock-in; 5+ letter words allow 1 typo (OSA distance); short words exact; number words = digits; whole-phrase alias match | Progress is never wasted; typos don't punish; "cat" never matches "car" | Position-agnostic locking: guessing "the" locks one "the". Acceptable since initials already reveal it |
| 8 | Fairness | Points by reveal stage (500→100), not milliseconds; +50 first solver; 20/word partial credit; final round ×2 | Typing speed matters less; trailing players can catch up | Two players solving in the same stage score the same (by design) |
| 9 | Min players | 2 to start a Party game (was 3). Duo rule for Set rounds: the author scores when the opponent solves after the first stage, since "some but not all" is impossible with one solver | Owner wanted to try it with one friend; duos are a common way to play | Duo Fake rounds have only 3 options, so they are easier to guess |
| 10 | Rounds | Round mix cycles Crack → Fake → Set; final round is always Set (×2) when phrases exist; Set rounds without enough prep phrases become Crack | Everyone gets knowledge, bluff and creativity turns; the finale is about the group itself | Fixed rotation; a host-configurable mix can come later |
| 11 | Prep | 75s prep (spec said 60s) for 2 phrases; ends early when everyone's done; late joiners get prompts too | Playtesting intuition: two thoughtful phrases on a phone keyboard need more than 60s | Slightly longer pre-game |
| 12 | Fake validation | A fake must match the initials (same word count, same first letters) and must not be the real answer; identical fakes are merged and share points | Keeps the initials constraint central (differentiates from generic bluffing games) | Strict: "12" must be answered with a word starting with "1" |
| 13 | Moderation | Short built-in blocklist (English + common Hindi slurs) for names always, and for player text when Family mode is on; host can hide any fake and skip any round | Zero-latency, no external API, covers the obvious cases | Not ML-grade; misses creative spellings. Add a moderation API if public rooms launch |
| 14 | Database | D1 with raw prepared SQL (4 tables). No `database_id` in config: Wrangler auto-provisions the database on first deploy. The Worker applies its own idempotent schema (`CREATE ... IF NOT EXISTS`, once per isolate) instead of a migration step | Zero manual DB setup in any environment, including Workers Builds | Schema changes beyond additive ones will need a real migration step later |
| 15 | Built-in packs | Six launch packs (≈270 items) live in code, not D1; only custom packs live in D1 | Packs ship with deploys, are type-checked, need no seeding, and load with zero latency | Content changes need a deploy |
| 16 | Daily | Puzzle per day = fixed seeded shuffle of all built-in items (day 1 = 2026-11-01 UTC). Guesses are checked server-side and stateless (client sends locked words + stage) | Answer never ships to the browser; no per-user storage; archive works for any past day | A determined user can replay a day; stats can be inflated by scripted requests |
| 17 | Room lifecycle | Rooms are created explicitly via `POST /api/rooms` (codes for unknown rooms are rejected); idle rooms are wiped 6h after the last activity; one live socket per player (newer tab wins) | Prevents typo-codes creating ghost rooms; frees codes; avoids double-acting players | A player with two tabs open loses the older one |
| 18 | Identity | No accounts. A random token in localStorage identifies the seat; rejoining with the same token restores score and seat | Zero friction from link to lobby | Clearing storage = new player; no cross-device history |
| 19 | Abuse limits | Guess rate limit in the reducer (3/5s); HTTP write endpoints limited per IP with the Workers Rate Limiting binding (20/min create room/pack/report, 60/min Daily guesses), failing open if the binding errors. (First version relied on a manual WAF rule; replaced so launch has no manual step.) | Limits live in code and config, tested by the smoke test | Per-colo counters, so limits are approximate; shared IPs (offices, schools) share a budget |
| 20 | Hiding answers | The host can hide *any* option in a Fake vote, including the real one (it then simply leaves the vote) | If hiding the real answer were refused, the host could probe which answer is real | A host can accidentally make a round pure bluff |
| 21 | Stage screen | `/stage/CODE` connects as a read-only spectator (`role=stage`), sees the public view only; no limit on stage sockets | TV mode with zero setup; phones stay the controllers | A room could get many spectator sockets; harmless at this scale |
| 22 | Web bundle | Separate `@initle/core/client` entry (no zod, no pack catalogue) + lazy-loaded routes. Initial JS ≈150 KB gzip (React, router, Motion) | Answers and pack data never ship to browsers; faster first load | Motion is the biggest single dependency; could swap for CSS animations later |
| 23 | Brand & theme | "Tile & Ink" game identity (replaced the first generic dark UI after owner feedback): grape-purple stage, cream letter tiles, thick ink outlines, hard offset shadows, pressable 3D buttons, Lilita One + Nunito, tilted/bobbing logo, stamps and confetti on big moments | A party game needs a playful, recognisable brand, not a dashboard look | Single theme, no light mode; Google Fonts dependency for the display face |
| 24 | Sound | Synthesized WebAudio effects + vibration, mute persisted locally | No audio files to load or license | Simple bleeps rather than produced sound design |
| 25 | Share card | Podium image rendered client-side on a canvas and shared via the Web Share API (download fallback) | No server-side image rendering (no WASM fonts in the Worker) | Look depends on the device's fonts having loaded |
| 26 | Daily records | Streaks/win% stored in localStorage; global per-day stage distribution in D1 | No accounts needed | Streaks don't follow you across devices |
| 27 | Security headers | Static `_headers`: CSP (self + Google Fonts), nosniff, immutable caching for hashed assets; `frame-ancestors 'self'` | Sensible defaults for a public web app | Must loosen `frame-ancestors` for a future Discord Activity build |
| 28 | Production deploy | Cloudflare Workers Builds (Git integration): Cloudflare builds and deploys `main` on every push. No API tokens or GitHub secrets. (A token-based GitHub Actions deploy was built first, then replaced at the owner's request.) Merging to `main` is the owner's approval to go live | Same token-free flow the owner already uses on other projects; credentials never leave Cloudflare | Deploy logs live in the Cloudflare dashboard, not GitHub Actions; CI (tests, E2E) still runs in GitHub |
| 29 | Tests | Engine: Vitest unit tests. Server: WebSocket smoke test against a real local Worker. UI: Playwright script (3 phones + TV, reconnect, Daily, packs) instead of a component test suite | Highest confidence per line of test code for a realtime game | Playwright is resolved globally (not a repo dependency) to reuse the system browser; CI installs it explicitly |
| 30 | Analytics | No third-party analytics (spec suggested PostHog). D1 `games` table records players, rounds, plan, packs and duration per finished game; `daily_stats` records Daily outcomes | No cookie banner, no extra script, no PII; covers the spec's core metrics (games/session, Daily solve rates) | No funnels or session replay. Add PostHog behind a consent prompt if needed |
| 31 | Scope | Quickplay with strangers, Discord Activity and AI pack tools are not built; they're the spec's post-launch phase (M4) | Spec gates them behind launch metrics; public rooms also need stronger moderation first | Separate projects once Party + Daily have traction |
| 32 | Hints | Built-in hints are checked by a test so they never contain a meaningful answer word | Several hand-written hints gave the answer away ("late", "Heist") | Test uses a small common-word allowlist |
| 33 | Fake fairness (review fix) | All Fake options are shown in one normalized format (Title Case, no punctuation/diacritics); a "fake" that equals the answer is accepted silently and dropped; fake submissions share the guess rate limit | Formatting gave the real option away; the error message was an oracle for the answer | Options lose original punctuation in the vote (the reveal shows the real title as written) |
| 34 | Kick (review fix) | Kicking bans that rejoin token for the room's lifetime | Otherwise a kicked player just reopens the link | A determined user can clear storage to get a new token |
| 35 | Lobby presence (review fix) | Disconnecting in the lobby marks a player "Away" instead of deleting them; the room creator gets host back on return; away players are pruned at start | A phone locking for 5 seconds used to cost the host their role and seat | Away players hold a seat until start or kick |
| 36 | Socket identity (review fix) | A socket that joined as one player can't re-join as another | Prevented scripted phantom players from filling rooms | None |
| 37 | Reactions (review fix) | Server-side reaction limit, 1 per 600ms per player | Client throttle alone could be bypassed | None |
| 38 | First live deploy | Set up through the owner's Cloudflare connection: created the `initle` Worker, connected `enrych/initle` via the existing GitHub link, and added a Workers Builds trigger for `main` (build `pnpm build`, deploy `cd apps/server && npx wrangler deploy`). The owner created the build token in the dashboard (the connection can't create tokens). The first build ran manually from `v2-m1` so the owner could play before merging; D1 was auto-provisioned. Live at https://initle.divyadityasnaruka.workers.dev | Owner asked for a live link to test with a friend | Live code is from the unmerged branch until the PR merges; after that every push to `main` redeploys |
| 39 | Pause | Host can pause/resume any timed phase; the remaining time is stored and restored exactly. Guesses, fakes, votes and prep are blocked while paused. The game auto-pauses when every player disconnects and auto-resumes when someone returns. Pause time doesn't count toward "Quickest Draw" | Groups stop for dinner, calls and arguments | A paused room with nobody connected is still wiped after the 6h idle limit |
| 40 | Mid-game settings | Every setting (round types, speed/timers, rounds, packs, family) can change mid-game; changes re-plan only rounds not yet started; timers apply from the next phase; rounds can't drop below rounds already played | The room changes its mind; the current round should never shift under players | Set rounds turned on mid-game only work if Prep happened (otherwise they fall back to another type) |
| 41 | Speed | Presets Relaxed / Normal / Fast (16s / 11s / 7s per reveal; prep, write and vote scale with them) plus custom sliders with safe limits. Normal is now 11s (was 8s, which the owner found too short) | One tap for most groups, full control for the rest | More settings to explain; presets keep it simple |
| 42 | Round types | Any combination of Crack, Fake and Set (at least one). If Set has no phrases left, its slot falls back to Crack (or Fake when Crack is off) | Groups that dislike bluffing can drop Fake entirely | None |
| 43 | Host tools | Next (skip prep/intro/reveal/scoreboard waits), End game now, Make someone else host (also becomes the lobby owner). Rounds now 3–20 in steps of one | Hosts asked for flow control without waiting on timers | None |
| 44 | Content & Daily | Packs grew from 266 to 515 puzzles, adding Famous Quotes and Places & Landmarks. The Daily order is frozen per "generation": the original 266 keep their exact day order and new puzzles are appended after them, so no past or current day ever changes | Adding content must not change today's answer | Each content release needs a new generation entry if inserted mid-pack (always append) |
| 45 | No-timer mode | Speed option "No timer": prep, reveal stages, writing and voting have no deadline; the host taps Next ("Reveal more letters", "Close writing", "Close voting"). Intro, reveal and scoreboard stay short and automatic. Switching timers on/off mid-phase applies immediately. Points still drop per stage revealed | Owner asked for no timer at all; some groups want to talk it through | The host has to keep the game moving; early-end still fires when everyone has answered |
| 46 | Playtesting as practice | I played full games myself (3 phones + TV, late joiner, solo) with a scripted playtest (`e2e/playtest.mjs`) that saves every screen, and fixed 14 issues it surfaced: two-row phone header, guess history, home explainer, guest settings summary, short phrases for Fake rounds, pack names, late-join welcome, "Start now" in Prep, hidden moderation toggle, TV "cracked it" banner, bigger TV tiles, leave confirmation, in-round help, Daily first-visit rules | The owner asked me to think like a real user instead of building to order | Playtest bots aren't people; real group playtests still matter |
| 47 | Solo endless | `/solo`: pick packs, crack puzzles back to back with no end. Guess-based stages like the Daily, a "Reveal more letters" skip, give up anytime. Points by stage plus a consecutive-solve bonus (+10 per solve in a row, capped at +100). Run and best stats live on the device. Stateless server endpoints (`/api/solo/*`) keep answers server-side and avoid repeats using the client's recent history | Players are often alone; solo play also feeds habit between parties | No global leaderboard (no accounts yet); history is per device |
| 48 | Daily streak | Streak shown on the home Daily card ("Keep your 2-day streak alive!"), in the Daily header, in the share text (🔥N), with toasts at milestones (3, 7, 14, 30, 50, 100, 365 days) | A visible streak is the main reason people come back daily | Device-only until accounts exist (v2.4) |
| 49 | Host on a TV | Home "Host on a TV" creates a room and opens the stage screen directly; the first phone to join becomes host | Living-room groups start from the TV, not a phone | None |
